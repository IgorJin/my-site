# Production checklist

Перед публикацией визитки:

- заменить demo `DATABASE_URL` на секрет из хостинга;
- настроить `WEB_ORIGIN` на реальный домен;
- перед запуском выполнить `prisma migrate deploy`;
- seed запускать только в отдельной demo-базе;
- включить HTTPS и ограничить CORS;
- настроить резервное копирование PostgreSQL;
- проверить `/health`, GraphQL query и contact mutation;
- не добавлять `.env` и реальные обращения в Git;
- настроить логи контейнеров и rollback предыдущего image;
- после публикации проверить мобильную версию и отправку формы.

В текущем Docker Compose API применяет миграции автоматически перед запуском. Для production лучше вынести миграцию в отдельный release job, чтобы изменение схемы не происходило при каждом рестарте приложения.
